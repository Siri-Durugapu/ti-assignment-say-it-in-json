# Say It in JSON — solution

Converts PipelineForge's `.pfcfg` config format (custom, includes +
conditionals + shell-style interpolation) into a documented JSON schema,
and proves the conversion is behavior-preserving by evaluating "effective
settings" two independent ways — once against the raw `.pfcfg` text, once
against the converted JSON — and diffing the results.

## Solution structure

| File | Role |
|---|---|
| `schema.json` | The target JSON schema (Draft 2020-12). |
| `SCHEMA-PROPOSAL.md` | Why the schema is shaped the way it is. |
| `parser.py` | `.pfcfg` text → AST (sections, key/values, includes, `@ifdef`/`@ifndef`). |
| `resolver.py` | AST → flattened `(section.key, raw_value, condition)` stream, with includes walked and conditions propagated. |
| `interpolation.py` | Parses a raw value into `literal` / `env` / `ref` / `concat` nodes. |
| `serialize.py` | Resolved stream → `schema.json`-shaped JSON, plus a provenance sidecar. |
| `run_converter.py` | **Converter CLI** — the runnable entry point for `serialize.py`. |
| `legacy_evaluator.py` | Reference evaluator: resolves effective settings directly from the raw `.pfcfg` tree. |
| `json_evaluator.py` | Resolves effective settings from the converted JSON — independently implemented, no shared code with `legacy_evaluator.py`. |
| `equivalence_verifier.py` / `run_equivalence_verifier.py` | Runs both evaluators on the same entry + environment and reports where they diverge. |
| `unmigratable_report.py` / `run_unmigratable_report.py` | Produces the JSON/NDJSON report of anything that can't be converted or resolved automatically. |
| `test_json_evaluator.py` | Focused checks of `json_evaluator.py`'s edge-case handling, plus a cross-check against `legacy_evaluator.py` on the real configs. |
| `examples.py` | Schema-design scratch work (worked examples used while shaping `schema.json`). Not part of the runtime pipeline — nothing else imports it. |
| `DECISIONS.md` | Design decisions, what the verifier proves/doesn't prove, known gaps. |

`acme-corp.json`, `globex.json`, `initech.json`, `conditional-includes.json`,
`interpolation-cascade.json` are committed reference outputs for the 5 real
starter entries. `<name>.regen.json` / `<name>.provenance.json` are the
same entries freshly regenerated by `run_converter.py` — see Step 1 below.

## Prerequisites

- Python 3.10+, standard library only for the pipeline itself.
- `jsonschema` if you want to independently validate output against
  `schema.json` (optional — the pipeline itself doesn't require it):
  `pip install jsonschema`
- The `starter/` sample configs, at `starter/configs/...` relative to
  this directory (i.e. unzip `starter.zip` here, not inside a
  subdirectory also named `starter`).

## Running it (~5 minutes)

All commands below are run from this directory.

**1. Convert the real starter configs to JSON.**

```
python run_converter.py --all starter/configs
```

Writes `<name>.regen.json` + `<name>.provenance.json` for the 5 real
entries (`acme-corp`, `globex`, `initech`, `conditional-includes`,
`interpolation-cascade`). This is the step that satisfies the
"converter `.pfcfg` → JSON" requirement as a runnable command rather
than just library functions.

To convert a single arbitrary entry instead:

```
python run_converter.py starter/configs/customers/acme-corp/pipeline.pfcfg starter/configs
```

**2. (Optional) Validate the output against the schema.**

```
python -c "
import json, jsonschema
schema = json.load(open('schema.json'))
v = jsonschema.Draft202012Validator(schema)
for e in v.iter_errors(json.load(open('acme-corp.regen.json'))):
    print(e)
"
```

No output means no violations.

**3. Run the equivalence verifier** (legacy evaluator vs. JSON evaluator,
against the real configs, under both locked fixtures — one CI-like, one
non-CI):

```
python run_equivalence_verifier.py
```

Expect `10/10 entry x environment combinations are EQUIVALENT`.

**4. Run the JSON evaluator's own test suite**, including its cross-check
against the legacy evaluator on the real `.pfcfg` trees:

```
python test_json_evaluator.py
```

Expect `ALL CHECKS PASSED`.

**5. Regenerate the unmigratable report:**

```
python run_unmigratable_report.py starter/configs
```

Writes `unmigratable-report.json` and `unmigratable-report.ndjson`. On
the current starter corpus this reports the 2 known circular-reference
keys in `interpolation-cascade.pfcfg` (`cascade.loop.a` / `cascade.loop.b`)
— see `DECISIONS.md` for what counts as "unmigratable" vs. a correctly
migrated edge case.

## Notes

- Steps 3–5 read the `.regen.json` / `.provenance.json` files written in
  step 1, so run the converter first.
- All 5 real starter entries and both locked fixtures are exercised end-to-end; the reported results are based on the actual starter files.
